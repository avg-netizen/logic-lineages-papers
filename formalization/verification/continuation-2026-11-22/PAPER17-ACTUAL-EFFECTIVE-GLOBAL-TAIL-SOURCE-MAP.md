# Executable original high-tail bound using a sufficient budget

[Paper 17 arithmetic.tex](../../../17-permitted-control-canonical-comparison/sections/arithmetic.tex)
105–162 fixes annotation and both transfer guards; 225–233 calls for
finite comparison/transfer labels before numerically choosing tails.

Compute the original annotation maximum over unchanged count-endpoint
bytes, and the existing finite prefix maximum from raw norm codes.
The pair maximum uses the literal safeTailCode normalization at
every typed prefix pair, P higher-candidate endpoints first and Q
lower-candidate endpoints second. Both inverse-table and original
gap-input components are retained. This maximum, as in #899/#918,
includes all ordered pairs of the candidate list, even impossible
ones; no cohort, valuation or actual collision oracle is used.

The code is primitive recursive for an alphabet, for the exact
depth collection through a supplied budget, and for a raw weighted
source whose budget is the proved sufficient length * 3^r. The
typed calibration preserves the original operand encodings and
the exact arithmetic bound on that larger bounded collection.
Endpoint legality and semantic success are not inferred from raw
codes, and the primitive leaf does not need the broad unrelated
class replacement proof.

Because the exact syntax charge is at most the sufficient budget,
every depth in the exact #918 collector appears in the sufficient
collector. The original alphabet-tail finite-max dominance then
gives an inequality: the executable bound is at least #918's exact
globalTail, not claimed equal to it. An explicit payment of the
executable bound at each original input rank supplies #918 payment.
The original actual domain/longness/ordinal branches stay separate,
as does the nonzero terminal sign cutoff.

No automatic valuation payment, term/domain validation on malformed
codes, complete symbolic decision tree, uniform order normalization,
or dimension-induction claim.
