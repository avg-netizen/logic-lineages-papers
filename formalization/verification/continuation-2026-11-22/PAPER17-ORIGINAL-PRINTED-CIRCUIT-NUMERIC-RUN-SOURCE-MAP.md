# Checked finite-bank numeric driver for the original ordered circuit

Paper 17, `17-permitted-control-canonical-comparison/sections/arithmetic.tex`, lines 3–11 and 33–54. This consumes the actual single-gate numeric code #1024 on each original gate in schedule order.

- The raw driver takes a finite initial bank and a literal list of original gate codes. It checks destination capacity before using the actual reader, whose parser separately checks every input. Code 0 is input-parser or output-capacity rejection, not a semantic gate hit. Existing codes 1/2/3 remain distinct. It writes the exact value of a hit into the one original destination and keeps bank length. Once any error is returned, every later gate preserves that first code.
- On a supplied typed topology with every initial known name and every original output within bank capacity, the proof derives all current input availability from this topology instead of assuming future values. The original bank decoder commutes with actual typed valuation update at that named coordinate. Exact calibration matches the original typed run on the whole finite sequence: success banks have the same length and exactly decode the actual final valuation; failure preserves the exact original numbered gate-rejection reason.
- The bank write/status dispatch is primitive recursive, and the driver is **Computable when (f) is Computable**, using the already paid actual reader plus one finite fold. The proof does not claim primitive recursion of the entire driver, correctness of unsupported finite output capacity, a parser for arbitrary original DAGs, coded terminal evaluation, a sufficient cutoff or a quantified decision.
