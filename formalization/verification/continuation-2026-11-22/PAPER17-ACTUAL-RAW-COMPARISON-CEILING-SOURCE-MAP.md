# Paper 17: exact executable original comparison-ceiling budget

Printed source: `arithmetic.tex`, mixed original value comparison and the
finite comparison-threshold component of the stage cutoff in
`thm:arithmetic`.

- An original bare coordinate or iterate-zero operand is not a
  separated comparison label. Ordinary value labels preserve the
  exact rank and field. A count uses the already exact raw proper
  classifier and full leading label; malformed/short counts do not
  emit a label. The code is calibrated only on literal typed operand
  encodings, not a general raw validator.
- Pair positions keep all original labels, duplicates, ranks and
  the actual left/right field labels. The comparison cost takes the
  larger of the two exact oriented costs, each of which also includes
  its exact literal upper-ordinal read bounds. No arbitrary pair cost
  supplier and no approximate numeric comparison.
- The original sufficient budget, not the smaller semantic charge,
  selects the finite raw zero-edge alphabet, in the established depth
  and literal operand order. Max over the exact ordered pair tape
  calibrates to the existing `comparisonCeiling` at that original
  budget. It does not assert all generated candidate fields are live
  or present in an actual branch.
- The label, pair, alphabet and row cutoff code are primitive recursive
  using the already exact source graph, ordinal bounds and budget
  programs. No stage-wide high bound, measured read or typed
  normalized route/order theorem, raw solver, or numbered promotion.
