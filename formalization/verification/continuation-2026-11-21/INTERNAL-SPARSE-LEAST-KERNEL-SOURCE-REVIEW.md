# Sparse least kernel: source-only review

The literal ordered-pool preservation theorem is already accepted. What is
not supplied is a genuine arbitrary-open derivation from a successful graph
of the selected physical least program to provenance in its actual ordered
rounds. This review is a proof route, not a new theorem or native result.
References below name source modules and their declarations.

## Actual algorithm and existing credits

- `NumberedWindowScalarAlgorithm.least` passes the actual directed
  `edge s ctx requested`, `vertices s seed`, and the seed to
  `NumberedWindowClassAlgorithm.least`. In that module, zero rounds
  filter the literal pool for seed equality. `advance` filters the same
  pool for a prior member equal to the candidate or an edge **from** that
  member to the candidate. `members` uses exactly the pool length as fuel;
  `least` is `List.min?` of that final list. Order and duplicate
  occurrences are retained by filtering; an absent seed is not inserted.
  The scalar edge includes original guarded exchange and admission of
  both endpoints at the same context and requested type.
- **#683** `NumberedWindowRawClassSaturationChecks`:
  `exact_LiteralClassSaturation`, `exact_SamePoolLeastSelf`,
  `exact_RawLeastResultAdmitted`, and
  `exact_RawLeastClosureWithVertices`. This proves the actual
  list/saturation and same-pool least-self laws. Raw closure needs the
  edge/pool invariant to identify the output's own pool, and the
  admitted-output conclusion requires seed admission.
- **#687** `NumberedWindowRawExchangeVerticesChecks.exact_OriginalGuardedEdgeVertices`
  discharges the literal pool condition. The proof
  `NumberedWindowRawExchangeVerticesVerticesProof.exactVertices` uses
  both original syntax bits and preservation of the actual
  `(nodes,maxNumeral)` term bound under guarded exchange. Thus
  `NumberedWindowCoverBoundsAlgorithm.cover` calls the same grammar
  with the same inputs, giving literal ordered-list equality, not
  merely equal membership.
- **#691** `NumberedWindowConcretePositiveEndpointsScalarProof.rawEndpoints`
  and `scalarEndpoints`, exposed by
  `NumberedWindowConcretePositiveEndpointsChecks`, use these laws for
  original positive endpoints. Boundary hops furnish admission and
  successful original least, and address parsing furnishes the actual
  endpoint coordinates. The numerical conclusion is original
  `scalar s` on those same positive endpoints. It does not yield an open
  object derivation for a physical scalar callback, or admission of an
  application seed.
- **#665** `NumberedWindowAtomicApplicationChecks.exact_AtomicAuxLeast`
  already gives both numerical provenance directions at literal
  free/bottom-headed tag-six applications.
  `NumberedWindowAtomicApplicationRoundsProof.atomicLeast` uses
  `List.min?_eq_some_iff` for membership and then `finiteRounds`.
  `NumberedWindowAtomicApplicationExchangeProof.scalarExchange` gives
  the one-edge case by the actual earlier-table row equation
  `NumberedWindowAtomicApplicationTableProof.rowAuxPair`. Literal
  annotations and atom persist; an equality stutter adds no edge.
  In both directions the `ArgumentMoves` trace is oriented from the
  raw seed to the least result, not reversed by recognition.
- **#668** `NumberedWindowAtomicApplicationReductionTargets.AuxAcceptedHop`
  and the exact reductions in
  `NumberedWindowAtomicApplicationReductionChecks` use those numerical
  laws for atomic application hops on the original raw witnesses. The
  actual raw predecessor's right argument can move to the visible input
  argument and to the visible output argument. This is not a trace
  from visible input to visible output in arbitrary Settings.

## Smallest scoped physical supplier

Freeze a local physical kernel taking a **supplied literal ordered
pool**, fixed context/type and seed, and an explicit directed edge AST.
Keep the initial equality filter, exact pool-length recursor over the
same pool, and optional minimum (zero on failure, successor of the
selected code on success). Prove exact all-input evaluation at these
coordinates, including an empty pool, absent seed, and retained order
and duplicate occurrences. Do not replace the pool with a set,
deduplicated list, sorted list, or a new carrier.

The first useful open endpoint is successful option-min graph to
membership in the actual final round. Then use the actual round
successor graph to obtain a genuine predecessor-chain certificate:
from the prior round, equality stutters preserve the chain and a
successful directed edge appends its exact graph. This forward
provenance needs neither least existence nor symmetry. A supplied-pool
kernel is not yet the installed full least and should be labeled as
such. For a further open least-self endpoint, physical pool preservation,
saturation and minimum comparison must also be proved, not inferred
from numerical #683/#687.

`NumberedWindowInternalSparseFieldParserTargets` supplies exact
ordered scratch conversion and open nil/cons/rejected-tail endpoints.
`InternalRawListRecursionTargets.ActualOriginalListRecursionZero` and
`ActualOriginalListRecursionCons` are candidate recursion components
on the **Nat.pair scratch** representation, not directly on the
sparse `(a+b)^2+a` source codec. Preserve the explicit bridge and
malformed-input behavior.

The full physical supplier must run the actual unpack check, feed the
actual ordered `vertices` list to this kernel, and use the original
directed edge. The atomic argument-trace endpoint additionally requires
physical edge success to expose the guarded tag-six row split and
the same actual child row. A numerically calibrated opaque exchange
program would leave the same reflection gap. This row reflection and
the full original cover/edge installation remain open.

## Installation and boundaries

uses `allPrimitiveFunctions` for the numerical
`ActualLeastCalibration`; `NumberedWindowScalarProgramProof.leastPrim`
and `NumberedWindowClassProgramTargets.ClassPrograms` are also
numerical compilation, not arbitrary-open ordered-round reports.
Do not infer a new object's graph from evaluation equality or replace
the old `leastWitness` in an existing derivation. Reselect the actual
transparent least and rebuild its dependent physical programs and
installation proofs.

If the next goal is only literal atomic output shape, existing
**#671/#673** is narrower: the physical re-emission check yields the
open shape coordinates but explicitly does not yield argument
provenance. Neither that shape nor the proposed provenance by itself
gives an open application-result carrier. Original application seed
admission and least-self at the same original pool, and the link to
the actual installed scalar graph at the unchanged endpoint, must be
paid separately. General `RawMatching` also requires the actual
earlier result and a transformed positive certificate; it is not
part of this kernel.
