# Paper 16: native iteration and realization statements on module-system copies

Problem (root ledger, this round): the native statements mix the legacy native syntax closure with the
Mathlib ordinal layer. As legacy roots they exceed the gate's fixed memory cap by import footprint alone
(`NativeOrdinalRealizationTargets`: 1,573,864 kB against 1,572,864 kB, 2 s CPU), and a `module` root
cannot import legacy files.

What was done (Opus B, `opusB/twin/`): 653 module-system copies of the legacy native closure under
`LogicLineages/NativeModule/`, generated by `opusB/twin/make_twins.py`, indexed in
`opusB/twin/TWIN-MANIFEST.json` (original and copy hashes, body hashes, any diff). Each copy is the
`module` header, the original imports redirected to copies, `@[expose] public section`, then the original
body. 645 bodies are byte-identical; 8 differ by deletion of the single word `private` on a declaration
the public interface refers to (listed in the manifest). No tracked file was edited.

Gated on the copies, receipt `1795399156663919873-3256109` (660 modules, peak RSS 929,556 kB):
- `NativeOrdinalIterationProof.exact_NativeIteratorRealizesFullPrefix : NativeIteratorRealizesFullPrefix`
  and `exact_NativeIndexedCarrierOrbit` — the typed native iterator realizes a semantic iterate
  satisfying the orbit equations of convention (I) over the full prefix. The 59-line drafted proof
  compiled unchanged.
- `NativeOrdinalRealizationProof.exact_NativeRealizationClosure`, `exact_NativeLambdaRealization` — strict
  backward transport, downward closure and countable pointwise supremum of realization on the native
  terms, and the one-binder abstraction rule. The 53-line drafted proof compiled unchanged.
