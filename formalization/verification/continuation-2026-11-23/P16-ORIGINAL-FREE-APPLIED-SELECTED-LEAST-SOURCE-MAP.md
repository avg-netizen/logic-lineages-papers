# P16 the free-headed auxiliary is the actual selected application least

Source-only support for Paper 16 sections/ordinals.tex 113–127. The
original input auxiliary seed is not a claim about the actual selected
representative. An already accepted literal free-headed application
must be interpreted by a physically specific front end.

* NumberedWindowInternalAtomicAppliedLeastShapeProof takes the actual
  output equation for the physical selected k, and a second **actual**
  shape equation for the very same output y. Both use the genuine
  sparse address selectors. Functionality of rawContext/rawResult/
  rawLeast identifies the exact contexts, codomains and k. Transport
  the actual tag-six shape guard and field-2 head selector to that k.
  No open numerical equality reflection, cover closure assumption or
  claim that every least preserves arbitrary seed syntax.
* NumberedWindowInternalAtomicAppliedLeastBindProof retains the real
  original selected least call from outputReport. It opens the actual
  shape, obtains the pinned typed domain/codomain and compares the
  two descriptions in one relabelled context. The old argument raw
  field and the selected auxiliary argument field remain separate.
* NumberedWindowInternalFreeAppliedLeastProof consumes **one** held
  actual acceptance of refinedApplication (applicationGuard i least).
  The exact already-existing guard-forgetting proof opens the genuine
  original physical application frontend on the same [f,arg,y], which
  exposes its actual least call. The exact same acceptance reports the
  auxiliary free-headed shape on the actual y, given the original
  literal free f and actual stored-type equality. The two opened
  reports are joined without a second selected least or extra
  shape assumption on k. In particular this is valid when that
  exact least program is the original packed least AST; the theorem
  imposes no host fit to prove its open graph claims.

On calibrated original least and scalar inputs, the original all-input
application frontend calibration and existing atomic application
refinement calibration already give the unchanged original graph; the
open proof neither assumes nor uses that calibration. The body is
arbitrary and can be the exact refinedLiteral body, without changing
its even program. No least existence, scalar carrier or I of y,
successor classification at y, general forward rule or neutral
computability is inferred. Existing numerical
NumberedWindowAtomicApplicationChecks.exact_AtomicAuxLeast remains
separate, with its actual ArgumentMoves trace.
