# Paper 16: direction of strict-edge realization transport

This is a source correspondence finding, not a manuscript edit or new Lean acceptance. The [printed ground definition and lemma](../../../16-persistent-marking-termination-ordering/sections/ordinals.tex#L428) define realization by `α ≤ r(s)`, then say in line 435 that realization survives replacing a term by a strict predecessor. If `s ≻c t`, the source rank inequality is instead `r(t) < r(s)`. The [Lean closure contract](../../LogicLineages/PersistentMarking/OrdinalRealizationTargets.lean#L44) preserves realization from the smaller `t` back to `s`. The printed lambda proof (lines 445–449) and iterator proof (lines 478–495) use that same backward transport.

The actual source terms distinguish the directions. At the index type, `Z = λz.z` has no head mark. The only original strict constructor requires a successful mark, so the closed native rank of `Z` is zero. The [checked literal successor construction](../new-paper-set-2026-11-18/accepted/503-native-ordinal-successor-and-cap.json) gives the actual strict edge `successorInstance Z ≻c Z`. Its source rank is at least one, so it realizes the ordinal one while `Z` does not. This does not assert that the midpoint has rank exactly one. This correspondence argument is separate from the resource-stopped mixed native realization gate.

Suggested replacement for line 435, for author review: “If a strict predecessor realizes a value, then the original term realizes that value.” There is no change to the checked backward contract or the numbered register.
