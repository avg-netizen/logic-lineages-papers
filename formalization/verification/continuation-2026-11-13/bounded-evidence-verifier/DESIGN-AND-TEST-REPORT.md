# Bounded-memory evidence verifier: candidate, not adopted

## Preservation and architecture
Read the original rank-memo verifier in full. Original script and evidence remain untouched. This separate candidate reuses its closure/import walk, comment stripping/forbidden syntax, profile constants, all four object existence/hash checks, source/dependency mtime staleness, axiom allowlist/parser, requested namespace audits, required exact aliases, frozen hashes, final source rehash, and inherited checks. Read-only Git ls-tree/diff/rev-parse are explicitly authorized and use GIT_OPTIONAL_LOCKS=0. No Lean compiler or Git mutation is invoked.

Receipts are traversed in the original lexical path order (excluding latest.json). Each receipt and each failed receipt is written immediately as one JSONL record {path,receipt}; only latest successful source-matched rows/profile fields for requested closure are retained. Failed later attempts cannot erase prior successful evidence. Log paths are sorted and full normalized text is preserved as {path,text} records. Originals are never deleted. SOURCE-AND-OBJECTS and other small compatibility outputs retain their old schema. JSONL archives are new labeled names, not replacements for old JSON archives.

Memory is O(requested closure metadata + unique log paths + largest single receipt/log), not O(all receipt history + all log text). Hashing uses 1MiB chunks; JSON output uses iterencode rather than constructing a second large serialized buffer. Gzip level1 trades larger archives for less CPU; no content omitted. A single exceptionally huge receipt/log can still dominate memory. No extra dependency installed.

## Deliberate differences requiring review
Status is candidate-checks-passed-not-adopted or candidate-pending, never the old acceptance status. Frozen file is an explicit mandatory argument. Log capture is one sorted pass after receipt indexing instead of repeated reads during receipt enumeration; immutable logs are equivalent, but concurrent modification needs conservative detection. Initial source digests are taken before receipt streaming. Candidate hardening will reject changes between initial and verification reads. As in the legacy verifier, this is not an atomic filesystem snapshot and external cache restoration is not reverified. No full-root build, remote CI, mathematical adoption, or manuscript promotion is claimed.

Full v1 pass: 5,352 modules, zero errors, 145.88 seconds, peak RSS 73,300 KiB (~71.6 MiB). Complete archives contain 902 receipts, 322 failures and 12,156 logs. Against the requested accepted snapshot, every module source hash, object hash, native row and log hash is unchanged. 145 entire rows are identical; 5,207 differ ONLY in receipt pointer, now pointing to lexically later successful receipts (documented per-module in SNAPSHOT-COMPARISON.json). Axioms including namespace audit rows, frozen preservation, inherited preservation, profile, gates and required aliases are exactly equal. Therefore the observed differences are subsequent receipt reuse, not source/object/axiom changes. No full old verifier run was needed.

The executed bytes are preserved as verify_evidence_bounded_tested_v1.py, matching the run's verifier hash. Final verify_evidence_bounded.py adds two fail-closed concurrency checks identified during review: a source changed since initial receipt selection is rejected, and a selected log differing from the archived text hash is rejected. These checks do not remove any old check and do not change selection on immutable input. Final hardened candidate receives synthetic tests but has NOT received a second full-history run; coordinator serial-window review is required before that run or adoption. No packet is labeled accepted evidence, and original outputs remain intact.
