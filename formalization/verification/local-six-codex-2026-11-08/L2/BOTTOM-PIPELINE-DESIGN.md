# Bottom source construction

This is an implementation/dependency note, not a checked theorem. The
ForwardGuard packet alone is adopted; other acceptance status is in STATUS.md.

The concrete global selection is ordered as follows. First choose the original
calibrated leaves. Any bottom-only source/target parameter normalization must
come next. Then apply BottomRepresentative.baseData, whose guard uses the
validator of the eventual once-member-normalized tuple. Finally apply the
existing normalizeData exactly once. This selected Data precedes every finite
window and Gamma. All malformed-input/fallback semantics remain original.

BottomDescentTargets freezes two actual internal endpoints on that same tuple:
exact bottom-test preservation through every object-language iteration count,
and preservation by the selected fallbackRepresentative. Candidate proofs use
the actual transition choice and existing full-language PA induction. They do
not add a preservation field or calibration-to-derivability rule. Target-only
preflight and candidate acceptance remain pending.

The canonical-fold next step has a shorter path than another payload induction:

1. Split the actual root opening test. The rejected branch returns the selected
   representative of the original input. The checked leaf closure and program
   functionality recover this equation at the supplied fold output.
2. The accepted branch yields the literal original application constructors.
   Take the actual child fold outputs; existing certifiedAt gives their source
   validity and types. Existing rawValidity proves the reconstructed raw
   application's source validity at the same parameter.
3. Existing applicationBackward and combineRecover identify the supplied output
   with the selected representative of that raw application. BottomDescent then
   transfers the exact bottom-test output. Both original parent and reconstructed
   raw application have constructor tag two, whereas exact bottom has tag three.

This also supplies actualJ nonbottom under its original V/member/type premises,
which L1 may need for source application compatibility. No child shape induction
is needed: only their already checked source/type invariants are used.

Symbolic-Gamma bottom validity is a separate unpaid obligation. A minimal
calibration-preserving source selection is to normalize oldSource and oldTarget
ONLY when the exact bottom test accepts: evaluate that same old leaf at
[value,pair(left(parameter),0)], retaining the literal old leaf otherwise.
Native bottom decoding is Gamma independent even when decodeType fails; the
original Object decoder's totality handles every raw Gamma code. At a fixed
literal local context/type, the explicit new AST wiring can reduce the bottom
leaf to a closed old-leaf computation. Closed program evaluation can then be
represented internally. This does not justify reflecting an extensional
symbolic-Gamma calibration into the calculus.

The active shorter assembly, confirmed with L1, wraps ONLY the final original
positive-path checker in a guard rejecting an exact-bottom SUPPLIED canonical
source endpoint. All edge/path APIs remain unchanged. Native all-input
calibration of that wrapper must preserve the original relation and every
malformed/nonclosed-window fallback. L1 owns this new wrapper and its gate.
L2's frozen BottomApplication target pays the actualJ nonbottom fact needed
to reintroduce the output guard after the existing certificate lift. This
bypasses the global fold-output-to-raw-input bottom reflection for I(bottom).
Selected-representative preservation through descent is still needed to prove
actualJ nonbottom at the reconstructed raw application's source-valid input.

The guard can be branch(normalize(bottomTestAt0),one,zero). Existing
normalizeReject/zeroBranchIntro convert the internally derived not-one bottom
test into guard acceptance, while normalizeAccept/successorBranchElim prove
guard rejection at actual bottom. No new Boolean-range premise is required.

Quotient terminality and I(bottom) follow only after that concrete source
assembly. The native blueprint then requires I for EVERY bottom-headed spine
before type induction gives C(bottom) at arrow types. That spine stage precedes
C-to-I via inverse application; neutral saturation and multiset/constructor/
lambda/substitution remain separate unpaid internal derivations.
