The internal statements quantify arbitrary `InternalOriginalStepGuard.Data

    (InternalApplicationValidityStack.recursiveData old member).sourceValid

and hence the conjunction of these TWO unchanged validator ASTs:

    target = validator constantOne old.targetValid
    universe = validator member old.sourceValid

Both original source/target leaves are arbitrary. Neither is assumed sound,
related to the other or Boolean valued. The V wrapper tests exact-one outputs.
No new Data record, correctness field, assumed application closure or claimed
source-validity-to-type-membership implication is introduced.

For the existing checked canonical selection, specialize to
`old = data.oldValidity`, `R = data.oldEdge.targetRepresentative` and
`member = data.member`. This gives exactly
`V = (InternalCanonicalDescentSelection.validity data).sourceValid`. The

## Exact formulas and bound variable scope

`sourcePremises old member x t` is exactly V(x)=1 AND left(x)=t, using original
arithmetic Program graphs. `outputInvariant old R member y t` is exactly

    V(y)=1 AND (left(y)=t AND T(y)=y).

Fixedness is T-fixed, not R-, D-, B- or N-fixed. The input need not be fixed or
canonical. No successful-run or source-to-member law is a hidden premise.

`certifiedResult` is the actual existing `certifiedFold G D C y x`, retaining
BOTH original H(x)=1 and N(x)=y graph formulas. `certifiedOutput` is that
certification conjoined with `outputInvariant`. `hasCertifiedOutput` binds y
with the original `SourceComputabilityFormulaSupportProof.existsOne`; x and t
are both relabeled through Sum.inl beneath that binder. There is no
metatheoretic chosen natural output or replacement graph relation.

The payload induction predicate is deliberately uniform:

    P(p) := forall original x, requested t,
      right(x)=p -> (V(x)=1 AND left(x)=t ->
        exists y, certifiedFold(G,D,C,y,x) AND
          (V(y)=1 AND (left(y)=t AND T(y)=y))).

`payloadMatrix` uses two object variables, in the order x then t, and the
existing `InternalClosedPrograms.allBlock` binds both. The payload term is
capture-avoidably relabeled. Strong induction on p therefore supplies the
property for EVERY original packed child input at each smaller payload. It
does not hold one original x fixed, induct on packed child codes, or require
any size bound on normalized outputs.

## Five exact target interfaces

0. `ActualOriginalCanonicalFoldPayloadInvariant`: derive P(p) internally for
   every symbolic p and original derivation context. It does not assume the
   strong-induction step, a fold invariant, constructor closure, or child run.
1. `ActualOriginalCanonicalFoldCertifiedOutput`: from V(x)=1 AND left(x)=t,
   derive the original internally bound certified output existential above.
   No membership, canonicality, calibration, H or N-fixed premise appears.
2. `ActualOriginalCanonicalFoldOutputConsumer`: from those same two source
   graphs and an actual N(x)=y graph, derive H(x)=1 and the invariant at that
   SAME y. Original Program functionality must identify the independently
   produced output with y. The raw fold graph alone is not treated as success.
3. `ActualOriginalCanonicalFoldTypedOutput`: additionally require the actual
   separate member(t)=1 graph, and conclude H(x)=1 AND acceptance of the
   unchanged canonical typed checker at y,t. Arbitrary source-valid leaf
   inputs need not have a member type, so this premise must not be removed.
4. `ActualOriginalCanonicalFoldOutputContinuation`: from a derivation of the
   two source graphs, eliminate the internally produced output into arbitrary
   psi. The continuation quantifies every new variable type beta, relabeling
   j, extended context Delta and output term y. It receives preservation of
   all relabeled original hypotheses and a derivation of the single exact
   certifiedOutput formula, then derives relabeled psi. No output is supplied
   outside this original existential scope.

The statements are uniform in arithmetic derivation contexts. This does NOT
mean a context-uniform source-program compiler or a varying-source-context
calibration. No such external theorem is included.

## Concrete proof route; no assumed main work

The intended proof is original internal strong induction at P(p), using
`InternalStrongInductionTargets.ActualStrongInductionInstance` (or its schema
or rule). An arbitrary packed x and t are introduced inside the payload step.
Its exact right graph and two source graphs remain available throughout.

Internally split the Boolean acceptance of the actual openGuard G. Its output

### Accepted opening / original application case

Consume BOTH frozen opening interfaces, once their independent proof is
accepted: the accepted-opening factorization and its relabel-safe
continuation. Acceptance alone must expose the shared ten original witnesses:
parent payload, middle, children, arrow, domain d, codomain e, function payload

and member(e) graphs, original left/right selector graphs, original payload
constructors, and BOTH fp<parentPayload and ap<parentPayload bounds.

Functionality identifies that parent payload with the current induction p and
its codomain e with t. Instantiate the smaller-payload hypothesis at fp with
original fn and its arrow tag, and at ap with original arg and domain tag.
Their existential outputs f' and a' carry actual certified folds, V(f')=1 and
V(a')=1, and the exact preserved arrow/domain left graphs. These child
certifications are DERIVED from induction, never supplied as target premises.

Construct an actual raw application r at `[d,e,f',a']` by internal Program
totality. Obtain right-selector witnesses for f' and a' internally and use
reverse pairing to reconstruct the literal original typed-child constructor
graphs. Apply the checked validator application closure separately to:

1. `validator constantOne old.targetValid`, using its constant-one node graph;
2. `validator member old.sourceValid`, using member(e)=1 from the ORIGINAL
   opening, not from V(f'), V(a') or an assumed source-to-member theorem.

Both child branch acceptances come by eliminating the actual V conjunctions.
Recombine the two parent branch acceptances to obtain the exact V(r)=1.
The existing `applicationClosureAtPayloads` / `rawApplicationClosure` support

Obtain actual D(r)=y internally. The checked canonical-descent validity,
left-preservation and T-fixed laws yield V(y)=1, left(y)=e=t and T(y)=y.

There is no comparison of normalized output sizes. Only original child
