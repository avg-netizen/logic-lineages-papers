# Balanced large-branch finite guards

Source: paper08 `thm:balanced`, `eq:balanced-row`, `eq:balanced-L`, especially the finite guarded-preorder paragraph following actual-head block collection and greatest surviving coefficient dominance. This component constructs only the finite semantic large branch. Accepted balanced collection, collected dominance and literal affine syntax supply its mathematical dependencies.

The syntax is the existing `CommonHeadLargeGuards.Formula`. Head comparisons are fixed before valuation: equal normal `NONote` heads admit an input equality guard, and actual ordinal representation order determines the head part of the lexicographic key. Neither natural-number encoding order nor an arbitrary head oracle substitutes for ordinal order. The fixed-head construction is explicitly semantic/noncomputable here. A numeric-code implementation must later use the real encoded ordinal comparator and prove correspondence.

Each Boolean mask specifies membership or nonmembership for every original occurrence in an equal-head, equal-complete-input block. Its signed sum uses all coefficients, including negative ones. `maximalFormula` requires every strictly greater actual key to have zero block coefficient. Thus the chosen nonzero block is greatest among survivors, not necessarily greatest among original keys. Every original input is tested against the original signed row's threshold before collection. The empty row, duplicates, all-canceled rows, and arbitrary integer desired signs remain in scope.

The all-canceled branch is a comparison of two natural-valued lower expressions: literal `Affine.lowerPart E` and `Affine.lowerPart F`. Desired signs outside `{-1,0,1}` are false. There is no frozen constant replacement for an open outside remainder.

The actual source instantiation enumerates signed original atoms in left-then-right order. Its first m labels name literal `Affine.completeInput` expressions, including every original occurrence even if it later cancels. Labels m and m+1 name the literal lower parts. `sourceValuation` evaluates every one under the original certificate's lower part `C.1` and the SAME raw valuation. Labels are positions in this finite list of expressions, not new raw variables or independently varying basis entries. The support-free numeral-zero default only totalizes lookup outside the list; the label bound prevents the formula from accessing it.

`LiteralSourceLabels` calibrates the entire ordered evaluation list against the original row's complete inputs and two actual lower values, and states lower-expression genuineness when the shared certificate is genuine. The sign-equivalence target requires only genuineness of E and F, as does the accepted actual source dichotomy. It does not add a needless lower-certificate genuineness premise to the semantic assertion.

`sourceAmbient` explicitly retains the original pair's raw support. `OriginalSourceSupport` proves containment of all instantiated guard names in that ambient support, not equality: fixed truth/falsity and canceled comparisons can omit names. Complete-input terms use all shared basis entries, but they are included only for actually listed positive source atoms, exactly where the original source support includes that whole basis. When there are no original atoms, only the two literal lower parts remain and their support is contained in the original pair. No support is recomputed from surviving atoms.

The final target is an iff between evaluation of the actual finite formula and original large-input bounds conjoined with the exact integer sign of the original source E/F difference. Greatest survivors, distinct blocks, nonzero coefficients and extremum witnesses are not hypotheses. The accepted source dichotomy provides their semantic proof obligations internally.

This component does NOT claim raw-code formula construction, a total recursive balanced compiler, small-input exception enumeration, exact full-translation free-variable equality, or quantified decidability/Snyatkov. Those remain separate pending work. Draft only: root review, comparator compilation and freeze must precede candidate proof authoring. No proof, compiler run or Git action is included in this draft.
