# Next numerical proof frontier: source audit, not an implementation

The next independent upper-bound supplier after the decision chain is
`lem:window-locality` in the original `sections/ordinals.tex`. Its numbered
statement has **two** parts, symbolic internal terms and the constructed
numerical intermediates. The already checked observation-closure theorem does
not promote this lemma: it starts from ordinary input pairs and reasons in
finite opened observations, whereas this locality is uniform in a declared
finite subtype-closed window and reaches arbitrary admissible comparison
endpoints and the separate auxiliary numerical syntax.

## Symbolic side

State a subtype-closed finite list of actual types, and use the actual
declaration-retaining `DecisionInventory.auxiliarySupport` (not merely
ordinary `TypeSupport.support`) for admissibility. Retain the same ranked
signature and original head declaration after every retype. Pay the
following bounded suppliers before a joint six-sort derivation proof:

- Opening and persistent marking add no inadmissible type or declaration.
- A typed Select argument has its literal domain types and every type
  suffix in the window. The *same* typed full `Spine.apply` with actual
  `ownerCopies`, protected original lambda spine, simultaneous
  substitution, and marked extra append preserves admissibility.
- FAbs retypes to its original codomain and appends the original
  domain-typed name; Copy and Stat retain the original declared target
  head and use only the corresponding target-argument types; matching,
  split, removal, and coverage use actual endpoint positions.

The checked `DecisionSourceCallSupport.consumeSubtype` and
`DecisionSourceCallProof` are useful supplier models. Do not replace the
arbitrary window with the observed input pair, nor quietly require its
port/free-name guard in the numbered endpoint.

## Numerical side

Freeze a new raw typed carrier before proofs. It must separately represent
ordinary original heads at omega, numbered heads with finite natural labels,
typed bottom, and auxiliary application distinct from the original
`Head.app`. The positive raw rules include an actual numbered decrement,
whole typed Select, Copy, primitive strict replacement, FAbs, beta and
bottom; contexts close every original head base/extra position and lambda
body but only the function side of auxiliary application. The primitive
mark-decrease relation preserves all old arguments and decreases the leading
label through initial lambdas, with no label-zero reuse. Preserve extra order
in the actual finite equivalence. Every numerical head retains its original
base declaration and result-type guard despite the current output annotation.

After a raw typed window-preservation supplier, separately check the whole
tuple lemma: for literal defined symbolic application prove an actual
finite path to the corresponding result, at threshold n with no more than
length+1 additional units. Consume only the original lambda spine, make
an available finite mark if needed, then do the required ordinary
auxiliary abstraction/beta steps. Definedness, not a weakening of the original
variable-headed case, excludes protected overapplication. Only then assemble
the six-sort weak/strict simulation with constructive budgets and a positive
strict path.

No historical Paper06 theorem or external ordinal-analysis assertion pays
these new proof obligations by itself. No proof/comparator was changed for
this roadmap.
