## Numerical targets

`AddressPositiveComposition` is analytic composition of the original
all-input calibrated validity programs and selected same-fiber fold.
For malformed terms and shape failures, the relevant original
`addressView` cannot return data and selected conjunction rejects.
Derive the actual tag3/three-field shape in a new local support lemma
from existing nodeArity/literalEvaluation/codeOfNode, not by editing
the private old outerShape lemma. Valid selectors return literal fields.
For true contextView both sides, existing `contextCode` (#649)
identifies raw packed code with `pack` at the decoded stack; injectivity
of original `unpack` on these exact inputs identifies raw equality with
the original decoded-stack equality. Actual result equality is literal.
Selected #643 fold then sees the same original typed stack via actual
unpack, unchanged input cert, and actual source/destination classes.

`ConcreteAddressPositive` supplies actual executable context and type
validity programs together with the same proved actual raw5/least3/
advance/fuel/fold choices. The public original PR witnesses are
`NumberedWindowAddressProgramProof.contextPrim` and `validType`; turn
actual defined Bool output to its original 0/1 code with the retained
unary program compiler. Every proof uses the same tuple. No new oracle.

## Open exact target

`OpenAddressPositive` retains actual object graph 1 at both physical
addressGood checks, all six selector observations with *one* shared
packed ctx and literal type, and original context/type guard graph
values 1. Since the witnesses are shared, the two actual occurrences
of each validity call have the same input; soundness still proves the
literal two checks in the AST. The original selected fold graph 1
uses the same two class values and actual unchanged cert. The true
object existential block binds [ctx,type,sourceClass,targetClass] in
that order and no other source/certificate variable.

Forward choose actual selector reports by original graph totality,
recover actual Boolean conjunction/shape/typed guards, use original
equalityTest output to align the real ordinary terms, transfer the
true right observations to the same ctx/type, and recover actual fold
composition. Reverse introduces each actual selector/callback graph,
same-field reflexive equality and genuine fold composition, proving
the entire real AST graph at 1. No assertion of semantic behavior
for unknown validator/raw/least programs is used as an object rule.

`sourceBody (data i j r d) c`, the fixed program tuple #596/#642, or
any open proof tied to that old syntax. A fresh exact full tuple
(including actual d/i/j/p and concrete scopes as needed) and original
object source-body rules/interpretations must be reinstantiated.
Full typed raw/least compatibility, general matching and paper16
arithmetic-accessibility remain unpaid.
