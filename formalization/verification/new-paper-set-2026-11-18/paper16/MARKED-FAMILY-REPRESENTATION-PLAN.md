# Concrete marked-family representation proposed for next freeze

Prerequisites: accepted full hereditary finite-lattice theorem; current MarkedExtras ten contracts (not yet native accepted) enumerate canonical downsets and actual weakening. Source remains decision.tex(C).

A family parameter is literal (head f, output type τ, port context Γ, base tuple List Code, extras List Tagged). Enumerate distinct finite source heads from the actual input, distinct τ in K, every WF context, every positional base tuple from actual descriptor carriers at f.arguments, and every canonical enumerated extra downset. Preserve original head identity/arity/order/repeated base positions. A coordinate bound is the cardinality of the actual output carrier DτΓ.

A family code is a Nat vector fitting these exact bounds; its lookup yields an optional output index and actual output carrier lookup. Define executable filters for (i) monotonicity under componentwise actual base order and literal extra inclusion; (ii) equation(C) under every actual context extension, actual positional base restriction and actual extra image-downclosure weakening. Both tests require successful actual output lookups; no defaults count as success. No observation/availability fields are additionally constrained.

Uncoded family is a function on the literal parameter fields. Validity includes actual output membership at enumerated valid inputs, monotonicity and(C). Equality is only on valid enumerated parameters, not unrestricted function equality. Prove exact vector Fits/semantic encode/decode with all valid missing-index failures impossible. Finite retained enumeration and actual output-domain joins/meets then give coherent-family lattice by pointwise lower restriction preservation, including empty families. The code vector tables use only global descriptor identity, never parent-dependent callbacks or across-context integer equality.

The parameter enumeration proof must include an explicit source-input bridge: every source head and each original declared base argument type is represented by the accepted auxiliary declaration inventory. If a preliminary builder accepts an arbitrary finite head list, source correspondence still derives the actual input list and K coverage internally before final source promotion. It cannot merely assume arbitrary arity tuple compatibility from the caller.

First supporting freeze can isolate literal base tuple product enumeration, restriction and monotonicity (actual TupleValues on f.arguments), plus parameter key enumeration/exactness/distinctness. Full family validity/coherence/lattice scope follows with actual code definitions. Downset adequacy and interpretation/operator are separate; no claim that pointwise finite family construction alone proves syntax completeness.
